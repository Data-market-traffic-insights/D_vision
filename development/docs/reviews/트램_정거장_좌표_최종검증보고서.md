## 2. 작업 범위와 방법

이전 두 보고서, 45개 검토표·미완료 목록, 217번 후보 CSV·도면/지도 증빙, 운영 좌표 CSV와 기존 후보·승인 코드를 재사용했습니다. 45개 도면을 처음부터 재분석하지 않고 요청서의 우선순위 **217 → 202 → 233 → 238 → 220 → 205 → 223 → 201 → 211 → 245**의 10개에 한해 도면 세부 구간과 실제 지도를 1차 대조했습니다.

이번에는 성공했던 브라우저 OSM·네이버 지도 경로만 사용했습니다. 이전에 실패한 Python/Overpass API 요청을 반복하지 않았습니다. 상가 데이터의 주소·좌표는 해당 도로 주변으로 **초기 지도 화면을 이동하는 데만** 사용했습니다. 상가·시설 대표점을 정거장 좌표로 복사하지 않았습니다.

후보는 공식 도면의 승강장 구간을 도로·교차로·주변 블록과 대조한 뒤 도로 위 점을 직접 선택하고, OSM의 **우클릭 → 주소 보기**에 나타난 위도·경도를 읽어 기록했습니다. 선택점과 다른 주변 피처의 주소 핀이 함께 보일 때는 둘을 구별했습니다. 역지오코딩으로 주변 시설 이름이 반환되었다고 정거장 위치가 검증된 것으로 처리하지 않았습니다.

지도 경위도는 EPSG:4326 도 단위 후보입니다. CAD 좌표계를 추정하거나 DWG를 변환하지 않았으며 공식 좌표를 새로 확보한 것은 아닙니다. 예정 위치 변경·지도 표현·도면 지리참조 부재에 따른 불확실성은 남고, 근거 없는 정량 오차를 쓰지 않았습니다.

## 4. 승인 처리와 운영 데이터 보존

기존 `coordinate_registry.candidate`를 사용해 별도 후보 자료를 생성했습니다. 승인 함수 `approve`와 운영 저장 함수 `save`는 호출하지 않았습니다. 승인자·승인일·승인 증거는 공란이며, 기록자에 코드 에이전트가 기재되어 있어도 승인자로 기록된 것은 아닙니다.

사용자는 위 5개 후보의 검토 질문에 **“추가 검토가 필요하니 후보로 유지”**라고 답했습니다. [검토 결정 JSON](../../results/station_final_review_20261104/review_decision.json)에 이 결정을 기록했습니다. 코드 에이전트가 검토자 역할을 대신하거나 승인 이력을 만들지 않았습니다.

따라서 `data/tram_stations.csv`는 바이트 단위로 그대로입니다. 기존 승인 5개의 좌표·출처·검증자·일자·이력도 보존했습니다. 후보를 운영 CSV에 미승인 상태로 옮기는 작업조차 하지 않고 별도 파일에만 보관했습니다.

추가 파일은 `station_coordinate_review.py`, `test_station_final_review.py`, 이 보고서와 `results/station_final_review_20261104/`의 후보·증빙·검토표·테스트·보존 기록입니다. 기존 기능 코드나 UI의 수정은 없습니다.
