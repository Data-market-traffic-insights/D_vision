## 1. 원본 보존과 검사 방법

원본 ZIP의 SHA-256은 `34916a84509a5411e8ea84c1b43edd4e84e2590635b56dd8b324e21d9ae503d3`이다. macOS 리소스 포크인 __MACOSX/._*.dwg는 실제 DWG로 세지 않았다. CP437로 표시된 ZIP 파일명은 원래 UTF-8 한글로 복원하고 NFC로 정규화하여 별도 originals/ 폴더에 추출했다. 추출한 13개 DWG의 원본 바이트 해시와 검사 후 해시가 일치한다. ZIP 및 원본 DWG를 수정하거나 재저장하지 않았다.
현재 설치된 CAD 판독 도구가 없어 Homebrew의 LibreDWG 0.14를 설치했다. dwgread로 헤더·문자·레이어·블록·딕셔너리를 JSON으로 읽었다. 1공구는 JSON 직렬화에 잘못된 숫자 표기가 생겨, 원문을 임의 보정하지 않고 dwg2dxf의 ASCII DXF 변환본을 따로 읽었다. 판독 로그에는 일부 클래스·프록시 객체에 대한 경고가 있으며 모든 비표준 객체의 완전한 해석을 보장하지 않는다.
기존 프로젝트 가상환경이나 앱 의존성에는 패키지를 추가하지 않았다. ezdxf는 DXF 분석에 사용할 수 있지만 DWG를 직접 변환하지 않으며, pyproj는 원본 CRS가 확인되어야 의미 있는 변환을 할 수 있으므로 이번에는 추가 설치하지 않았다. 대용량 검사 중간파일은 내용 해시를 검증한 후 GZIP 압축본으로 보관했다. 압축으로 치환한 것은 이번에 생성한 JSON/DXF 변환본이며 원본 DWG가 아니다.

## 3. 좌표계와 지리참조 조사

- 13개 모두 헤더 LATITUDE=37.795, LONGITUDE=-122.394로 동일했다. 대전의 위치가 아니며 AutoCAD에서 지리 위치 미지정 시 사용하는 샌프란시스코 기본값과 일치한다. 정거장 좌표로 사용하지 않았다.
- 판독된 GEODATA는 모두 0개였다. 텍스트·속성·확장 데이터에서 EPSG 코드, WKT/투영 정의, GRS80/Bessel/WGS84 측지계 선언, 중부원점·세계측지계와 같은 명시적 근거를 검색했으나 확인하지 못했다.
- 큰 배치도에는 Autodesk Map 관련 딕셔너리나 옛 지형 데이터 블록이 있지만, 표시 스타일·편집 설정 자체는 CRS 선언이 아니다. 조사한 판독 가능 필드에 투영/측지 정의가 없었고 일부 객체는 판독 제한이 있다.
- 4공구 도면은 여러 방향의 실제 도로를 도면에서 가로 방향으로 배치하고, 정거장마다 삽입 기준점·원점과 도면 위치가 다르다. 일부 도면 외곽 크기는 84,100×59,400 또는 그 배수로 나타나 도면 프레임과 축척 편집을 포함한다. 도면상의 X/Y를 그대로 국가 좌표로 간주할 수 없다.
- 블록 정의, 축척·회전된 삽입, 표제란, 측점 문자와 실측 지형 좌표가 섞여 있다. 큰 숫자가 한국 TM 좌표처럼 보인다는 이유로 EPSG 코드를 선택하거나 X/Y를 1,000으로 나누어 위경도를 생성하지 않았다.
- 삽입 원점이나 문자 위치만으로 승강장 중심의 지리좌표를 산출할 수 없다.

근거 문서: [Autodesk LATITUDE 기본값 설명](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-LT/files/GUID-BBA986D3-9BA8-4160-9471-55DAC9EDCA70.htm), [Autodesk INSUNITS 정의](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-A58A87BB-482B-4042-A00A-EEF55A2B4FD8.htm), [LibreDWG 도구 설명](https://www.gnu.org/software/libredwg/manual/html_node/Programs.html).

## 5. 운영 데이터 반영과 실제 반경 분석

이번 검사로 좌표가 검증된 정거장은 없으므로 data/tram_stations.csv의 위경도·상태를 변경하지 않았다. 공식 WGS84 좌표 0개, 근사 WGS84 좌표 0개, 미확보 45개다. 도면 X/Y 또는 기본 위경도를 운영 CSV에 넣지 않았다.
기존 검증 조건과 반경 분석 차단 동작을 유지했다. 현재 실제 정거장 기반 300m·500m·1km 상가 집계·접근성·시나리오 노출 수치는 활성화하지 않았다. 새로 생산된 실제 반경 분석 결과는 없다. 기존 대시보드와 K-means 결과도 수정하지 않았다.

## 6. 검증 결과

기존 17개와 CAD 검사 4개, 총 21개 테스트를 통과했다. 검사한 ZIP·DWG 원본 해시, 각 파일별 검사 기록, 삽입 단위, 기본 위경도의 비사용, JSON 판독 오류의 DXF 대체 경로, 운영 파일의 해시·수정 시각 유지, 45개 미검증 정거장의 반경 분석 차단, DXF 헤더·문자 파싱을 확인했다.
명령은 d_vision_project 폴더에서 실행한다.
```sh

```

## 7. 다음으로 필요한 공식 자료

실제 좌표 확보를 진행하려면 다음 중 검증 가능한 근거가 필요하다.

1. 해당 도면의 측지계·투영법·원점·축 방향·단위가 적힌 설계/측량 기준 문서 또는 EPSG/WKT/PRJ 정의.
2. 편집·회전된 종이 배치가 아닌 지리참조 모델공간 원본과 예정 승강장 위치의 레이어/블록/객체 식별 정보.
3. 로컬 도면이라면 도면 좌표와 공식 측량 좌표가 함께 기록된 독립 기준점 및 축척·회전·이동 관계, 확인용 별도 기준점.
4. 또는 정거장 중심점 성과표·공식 좌표 CSV/GIS.

위 자료로 좌표계와 중심점이 확인되면 그때 WGS84로 변환하고 PDF의 예정 위치와 대조한다. 좌표계가 확인되지 않은 현재 상태에서 무리하게 변환하지 않는 것이 이번 검사 결론이다.
